# Собственная доставка отчёта через Google Apps Script

Необязательная интеграция. Используйте новый проект своего Google-аккаунта и файлы
`Code.gs`, `appsscript.json`. Манифест ограничен разрешением MailApp на отправку почты.

1. В Script Properties укажите `JOB_REPORT_RECIPIENT` — свой фиксированный адрес.
   Адрес не берётся из входящего запроса.
2. В локальном `delivery-config.json` задайте тот же адрес в `recipient` и
   `apps_script_recipient`, `recipient_confirmed: true`, `transport: apps_script`.
3. Создайте свой Web app deployment с выполнением от своего имени. Доступ должен
   позволять POST агента; передача защищена отдельным 64-символьным токеном.
   URL храните только в собственной конфигурации, не публикуйте его.
4. В своём терминале запустите:

   ```bash
   python daily_delivery.py --configure apps-script
   python daily_delivery.py --copy-apps-script-token
   ```

   Первая команда запрашивает ваш URL `/exec`, создаёт токен в Keychain, не отправляет почту.
   Вторая копирует токен в буфер macOS. Вставьте его в `JOB_REPORT_TOKEN` в Script Properties,
   затем очистите буфер. Не вставляйте токен в чат.
5. Один раз выполните `authorizeMailApp` в редакторе Apps Script и предоставьте разрешение.
   Функция читает доступную квоту, сама писем не отправляет.
6. После появления локального дневного отчёта и отдельного разрешения включите `mail_enabled`
   в `portable-config.json` и выполните один реальный тест:

   ```bash
   python daily_delivery.py --send-apps-script-test
   ```

7. Проверьте входящие и вложение `digest.html`, затем:

   ```bash
   python daily_delivery.py --enable-apps-script
   ```

   Команда требует успешной тестовой квитанции и вашего ввода `ПОЛУЧЕНО`, затем включает доставку.

В Apps Script попытка резервируется до MailApp; повторная/неопределённая отправка автоматически
не повторяется. Тест и обычный дневной отчёт имеют разные идентификаторы.
Проверьте доступность URL, разрешения, квоту и доставку на своей установке.
В сборке проверялись только локальные двойники сервисов Google.

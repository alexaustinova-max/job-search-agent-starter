# Проверка starter-сборки

Дата сборки: 4 ноября 2026 года. Полная интеграционная среда — macOS.

## Проверено

- Создано отдельное Python virtualenv вне исходного проекта. `requirements.txt` устанавливается;
  дополнительных Python-пакетов нет. Проверки выполнены на Python 3.14.
- Playwright 1.64.1 установлен в отдельную временную папку через npm, затем повторно установлен
  `npm ci --offline --ignore-scripts` из зафиксированного lock-файла. Модуль `chromium` загружается.
  В рабочем окружении прежнего владельца ничего не устанавливалось.
- 40 Python-тестов: новая пустая база и идентичность установки; один/несколько резюме;
  загрузка своих фактов и regex компетенций; выбор CV; изменения контрольной суммы;
  NET/GROSS, зарплатный порог, география, форматы, исключения и английский;
  поиск по локальному двойнику HH, лимиты, cooldown 429, дедупликация;
  локальные письма; дневной HTML и почтовое превью; резервирование AI-бюджета;
  сохранение неопределённых расходов/отправок; независимые запреты HH, AI, Chrome, почты и отправок;
  генерация plist без установки расписания.
- При повторной проверке отображения HTML, Markdown и архивного HTML подтверждено:
  зарплатные ожидания и NET/GROSS берутся из профиля, при незаданных ожиданиях сумма отсутствует;
  бюджеты и число вызовов OpenAI — из `llm-config.json`, часовой пояс и лимит откликов —
  из конфигурации этой копии. Изменение настроек отражается при следующем формировании отчёта.
- 4 JavaScript-проверки: три теста допуска к браузерной подготовке и один набор регрессионных
  проверок Apps Script на локальных двойниках Google. Набор проверяет токен, фиксированного
  получателя, контрольную сумму вложения, раздельную дедупликацию теста/отчёта,
  неопределённый исход, квоту и mail-only OAuth scope.
- Офлайн-демо: вымышленная вакансия, отдельная временная SQLite, подтверждённые вымышленные
  факты, черновик, повтор без дубля. Рабочая база пользователя демо-данными не заполняется.
- При тестах запрещены сокеты, HTTP, SMTP, `subprocess.Popen` и `ctypes.CDLL`.
  Реальные HH/OpenAI credentials, браузер, Keychain и почта не использовались.
- В архиве нет `.git`, symlink, virtualenv, `node_modules`, базы, логов, отчётов старых запусков,
  токенов, cookies и браузерного профиля. Проверяются распакованное дерево и ZIP-содержимое.
- Проверка приватности включает конфигурации, код, JS/Apps Script, документацию и примеры:
  личные адреса, пути, телефоны, токены/интеграционные URL, ID прежних пилотных вакансий,
  имена работодателей/фактов и длинные точные фрагменты прежних карьерных данных.

## Что включено и адаптировано

Использована реализованная архитектура: `hh_api.py`, `pipeline.py`, `daily_prepare.py`,
`prepare_batch.py`, `llm_prepare.py`, `application_batch.py`, `chrome_executor.py`,
`chrome_worker.mjs`, `daily_run.py`, `daily_delivery.py` и модуль DOM-проверки.
Сохранены SQLite-таблицы/события, hash-проверки, бюджеты, дедупликация, запрет повторной
неопределённой отправки и контроль подтверждения по истории HH.

В изолированной копии заменены персональные правила профилей, географии, зарплаты и писем
на пользовательскую конфигурацию. Удалены прежние карьерные тексты и пилотные разрешения.
Добавлены произвольные ключи резюме, возможность одного резюме, начальные выключатели,
проверка ID базы, локальный doctor/демо и генератор собственного plist.
Личный браузер через Apple Events отключён; используется только отдельный профиль внутри проекта.

`matching` остаётся детерминированной эвристикой по regex и фактам. Он не доказывает полноту
соответствия профессии или всем требованиям. Специфические требования нового владельца задаются
его критериями; черновики доступны для ручной проверки до включения автоматизации.

## Не проверено онлайн

- Получение/действительность собственного HH-токена нового владельца и доступность его API.
- Текущая разметка личного кабинета, страницы резюме, полей формы и истории HH.
- Запуск Chrome, сохранение новой авторизации и реальный отклик с подтверждением истории.
- Доступность выбранной OpenAI-модели, действующие тарифы и платная генерация/проверка.
- Доставка SMTP во входящие, права и публикация нового Google Apps Script Web app.
- Установка и реальное исполнение нового launchd-задания, доступ к Keychain из него.
- Полная работа на Linux/Windows и старших/других версиях Python/Node.

Эти функции сохранены и защищены проверками, но не объявляются проверенными на аккаунтах
другого пользователя. Команда синхронизации собственного HH-резюме требует его онлайн-проверки.
Модель оценки НДФЛ РФ за 2026 год унаследована и не перепроверялась как налоговая консультация.

## Исходная установка

Исходный проект использовался только для чтения и фиксации SHA-256/метаданных.
Исходный pipeline не запускался; его зависимости, база, Keychain, браузерная сессия,
launchd, доставка и процессы не управлялись и не перенастраивались.
Git-метаданных в исходной папке на момент сборки не было; Git-история не включалась.
Сравнение до/после и локальный отчёт о сохранности хранятся отдельно от передаваемого архива.

## Повторение проверок

```bash
python -m unittest discover -s tests -v
node --test tests/*.mjs
python portable.py demo
python portable.py doctor
```

`doctor` с ещё пустым профилем показывает `configure_one_or_more_resumes`: это ожидаемо.
`FILE_SHA256.json` содержит контрольные суммы всех файлов чистой сборки, кроме самого манифеста.

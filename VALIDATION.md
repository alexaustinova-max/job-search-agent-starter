# Проверка starter-сборки

Дата обновления: 6 ноября 2026 года. Проверки выполнялись в независимой копии.

## Проверено офлайн

- **92 Python-теста** и **10 JavaScript-проверок** на вымышленных данных, временных SQLite
  и двойниках HH, модели, браузера, SMTP/Apps Script. В Python-фикстурах блокируются сокеты,
  HTTP, SMTP, запуск процессов и доступ к системным библиотекам/секретам.
- Исходные 40 Python-проверок сохранены: чистая идентичность базы, одно/несколько CV,
  собственные факты/компетенции, matching, зарплата, язык, география, лимиты HH, дедупликация,
  локальные черновики, HTML/Markdown/почтовое превью, бюджет и выключенные интеграции.
- Новые проверки: обязательные квалификации до платной подготовки, полное письмо из
  fake-ответа модели, независимая проверка всех сегментов и ссылок на источники, привязка
  к вакансии/CV/фактам, reuse/cache и отсутствие самовольного разрешения отправки.
- Общий AI-бюджет, ужесточение лимитов работающей пачки, учёт незавершённого ответа,
  сохранение резерва после ошибки транспорта и запрет автоматического повтора.
- Профессиональные ответы, отдельная проверка и кеш; неизвестные/личные вопросы,
  согласия и тесты; явное подтверждение, область действия, изменившаяся карточка/контекст,
  лимиты UTF-16 и варианты. Локальный UI отклоняет чужой Host/Origin и неверный токен.
- История до AI: уже отправленная вакансия или неполное чтение блокируют расходы;
  JS-пагинация проверяет все три вкладки. Пустой набор ID не означает «все».
- Пауза во время проверки формы останавливает финальный клик. Подтверждённая/неопределённая
  история не освобождается; прерывание до клика требует свежего доказательства отсутствия в HH.
- Один дневной цикл, заданное время/часовой пояс, завершённый день без повтора этапов,
  продолжение сохранённой подборки/подтверждённых ответов и честный retryable-статус сбоя.
- Качество/воронка и email используют разрешённые поля. Apps Script сверяет получателя
  владельца в запросе и квитанции; JS-проверки сохраняют токен, checksum, dedup, квоты и mail-only scope.

Отдельное чистое Python-окружение использует стандартную библиотеку, requirements не добавляет
пакетов. npm устанавливает зафиксированный Playwright 1.64.1 через
`npm ci --offline --ignore-scripts`; модуль загружается без запуска Chrome.
Проверенная среда: Python 3.14, Node.js 24.14. Браузеры не устанавливались и не запускались.

ZIP проверяется по CRC, безопасным относительным именам, отсутствию symlink и приватных
файлов, манифесту SHA-256, распаковке в новую папку и повторным офлайн-тестам/демо.
`FILE_SHA256.json` содержит все файлы чистой сборки, кроме самого манифеста.

## Ограничения

Matching и отбор обязательных условий остаются эвристиками; они не доказывают полноту
соответствия профессии. Ответы модели в тестах — двойники, а не проверка реального качества AI.
Новая политика требует повторного осознанного принятия владельцем перед автоматическими отправками.

Не проверялись онлайн: HH API/OAuth нового владельца; текущая разметка CV, форм и истории HH;
сохранение логина Chrome; доступность и цены выбранной OpenAI-модели; платная генерация;
реальный отклик с подтверждением; SMTP/Apps Script во входящих; launchd и Keychain по расписанию.
Полная цепочка на Windows/Linux не подтверждена. Неопределённую отправку нельзя повторять.

## Рабочая установка

Исходная установка использовалась только для чтения и SHA-256/метаданных. Её код не выполнялся.
Зависимости, Git, SQLite, Keychain, Chrome, процессы, расписание и настройки не изменялись
действиями подготовки. Приватные снимки аудита находятся вне starter и не публикуются.

## Повторение

```bash
python -m unittest discover -s tests -v
node --test tests/*.mjs
python portable.py demo
python portable.py doctor
```

До `init` и собственного профиля `doctor` сообщает ожидаемую ошибку настройки. Он не читает
секреты и не обращается к сервисам. Подробнее: [START_HERE.md](START_HERE.md).

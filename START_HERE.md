# Job Search Agent Starter

## Быстрый старт: первые 5 шагов

1. Распакуйте ZIP на Mac.
2. Откройте папку `job-search-agent-portable` в Codex.
3. Откройте `CODEX_SETUP_PROMPT.md`, скопируйте готовый промт и отправьте его в Codex.
4. Codex проверит необходимое ПО и поможет последовательно настроить ваши резюме (одно или несколько), профессиональный профиль, критерии вакансий и необходимые подключения. Там, где потребуются личные действия, он даст пошаговую инструкцию.
5. Сначала проверьте поиск вакансий, качество подбора и сопроводительных писем. Автоматические отклики включайте только после проверки и отдельного разрешения.

Не нужно самостоятельно изучать всю техническую документацию перед началом. Начните с готового промта для Codex. Он проведет вас по настройке. Подробные инструкции ниже предназначены для настройки, проверки и устранения возможных ошибок.

Самостоятельная копия для **нового владельца**. Полный набор интеграций рассчитан на macOS:
HH-секреты хранятся в Keychain, расписание — в launchd, браузер — отдельный Google Chrome.
Linux и Windows для полной цепочки не проверялись.

## 1. Что внутри

Сохранены модули HH API, SQLite, дедупликации, matching, выбора резюме, локальных писем,
OpenAI Responses API с резервированием бюджета, дневного HTML-отчёта, Playwright/Chrome,
проверки истории откликов и доставки отчётов через SMTP или собственный Google Apps Script.

`portable.py` — первоначальная настройка и запуск. `portable-config.json` — независимые переключатели.
Рабочий профиль — `pipeline-config.hh.json`, карьерные доказательства — `career-facts.json`, резюме — `cv/`.
`examples/` содержит только вымышленные примеры; они не активированы. `tests/` — офлайн-проверки.
В архиве нет базы, ключей, сессий, истории, расписания и данных прежнего владельца.

Первоначально все внешние функции выключены. Простое открытие папки, `init`, `doctor`, `validate`
и `demo` не обращаются в HH/OpenAI, не открывают браузер и не отправляют почту.

## 2. Зависимости

Распакуйте проект в отдельную постоянную папку. Следующие команды выполняйте в ней:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm ci --ignore-scripts --no-audit --no-fund
python portable.py init
python portable.py doctor
```

Нужны Python 3.11+, Node.js 20+, npm и установленный Google Chrome.
Python использует стандартную библиотеку; `requirements.txt` не скачивает пакеты.
Playwright подключается к установленному Chrome через `channel: chrome`: скачивание Chromium не требуется.
Проверка сборки выполнена на Python 3.14 и Node.js 24.14.

Для расписания задайте в `browser-config.json` **свои абсолютные** пути к Node и локальному Playwright:

```bash
node -p 'process.execPath'
node -p 'require.resolve("playwright")'
```

Первый результат запишите в `node`, второй — в `playwright_module`.
Без расписания значения `node` и `playwright` также работают из терминала с настроенным PATH.
`native_arch` не требуется. Не используйте пути к окружению Codex другого человека.

## 3. Открытие в Codex

Откройте распакованную папку через выбор проекта в Codex. Начните с запроса из
`CODEX_SETUP_PROMPT.md`. Codex должен работать только в этой папке и сначала подготовить профиль.
Секреты вводите в собственном терминале со скрытым вводом, не вставляйте их в чат.

## 4. Свои резюме, факты и критерии

1. Положите одно или несколько своих резюме в `cv/`. Для локального просмотра подходят PDF,
   для текстового контекста также UTF-8 `.txt`/`.md`. Перед браузерными откликами нужен снимок своего HH-резюме.
2. Заполните `pipeline-config.hh.json`: `candidate.name`, `candidate.email`, `candidate.cvs`,
   `candidate.profiles` и `sources[0].searches`. Рабочим источником настроек является именно этот файл.
   Старый совместимый `pipeline-config.json` не используется командами `portable.py search/daily`.
3. В `career-facts.json` внесите **свои** подтверждённые факты, достижения и источники.
   `verified: true` ставьте после проверки. `letter_text` — допустимое утверждение для письма от вашего лица.
   `source` указывает на ваше резюме/документ; `scope` уточняет ограничения.
4. `profiles` и `cvs` должны иметь одинаковые ключи. Достаточно одного ключа, например `MAIN`.
   `title_patterns` — регулярные выражения для должностей, `capabilities` — компетенции,
   `priority` — целое число от 0: меньше — выше приоритет. У запроса HH `profile` ссылается на этот ключ.
5. Встроенные компетенции перечислены в `pipeline.py` (`CAPABILITIES`). Новые задавайте в
   `candidate.capability_patterns`: ключ → регулярное выражение. Используйте тот же ключ в профиле и фактах.

Пример для одного резюме находится в `examples/one-resume/`, для двух — в `examples/multiple-resumes/`.
Не заменяйте свой рабочий профиль демонстрационным после подключения реальных сервисов.

В `filters` настройте:

- `min_monthly_rub`, `desired_monthly_rub`, `salary_basis: NET` или `GROSS`;
- `cities`: допустимые города для офиса/гибрида; пустой список не ограничивает города;
- `allowed_work_formats`: `remote`, `hybrid`, `on-site`, `unspecified`;
- `exclude_title_patterns`, `exclude_text_patterns`, `required_text_patterns`, `excluded_employers`.

`desired_monthly_rub` сохраняет желаемый ориентир; жёсткая зарплатная граница — `min_monthly_rub`.
Ожидания в отчёте берутся только из `desired_monthly_rub` и `salary_basis`.
Если ожидания отсутствуют, равны `null` или `0`, сумма не выводится и не заменяется минимальным порогом.
Конвертация GROSS→NET использует унаследованную оценочную модель НДФЛ РФ за 2026 год:
для другой налоговой ситуации используйте GROSS и проверяйте условия вручную.
Неизвестная зарплата и неподтверждённые требования явно требуют проверки.

Формат `remote` сам по себе не доказывает разрешение работать из вашей страны.
Ограничения по стране, релокации и часовому поясу задайте своими regex в `exclude_text_patterns`
и проверяйте в подборке. Агент не доказывает наличие у вас юридического права на работу.

В `portable-config.json` настройте `timezone` (IANA), `max_vacancies` (1–90),
`max_search_requests` (1–30), `max_applications_per_day` (1–15), `daily_time` (`HH:MM`).
Для обычного `search` число запросов и деталей дополнительно ограничивают `sources[0].max_pages`
(1–2), `per_page` (1–20) и `detail_limit` (1–90). Общие переносимые лимиты применяются и к нему.
`daily` возобновляет поисковые курсоры и ограничивает дневную подборку вашим лимитом.

```bash
python portable.py validate
python portable.py doctor
```

Когда данные проверены, установите `profile_confirmed: true` в `portable-config.json`.
Это подтверждение своего профиля, отдельные интеграции пока остаются выключенными.

## 5. HH API и собственная браузерная сессия

Создайте своё приложение HH и используйте свои Client ID/Client Secret и контактный email.
Установите `hh_enabled: true` в `portable-config.json`, затем **в своём терминале**:

```bash
python hh_api.py setup
python hh_api.py status
```

`setup` получает токен приложения, если он ещё не задан, и выполняет один небольшой контрольный
поиск по вашему первому запросу плюс чтение описания. Это реальные HH-вызовы, откликов нет.
Вставленный ранее выданный токен используется без повторной выдачи. Статус `success: true`
нужен для дальнейшего поиска. При 401/403/429/CAPTCHA агент останавливается/ставит паузу.
Он не обходит проверки и не выдаёт повторные токены автоматически.

Секреты изолированы идентификатором установки и путём папки в вашем Keychain.
Перенос уже настроенной папки в другое место потребует заново подключить её секреты.
Не копируйте чужой браузерный профиль или Keychain.

Для собственного Chrome установите `browser_enabled: true`, проверьте профиль и войдите вручную:

```bash
python application_batch.py --browser-profile-check
python application_batch.py --browser-login
```

Проверка кратко переключает и восстанавливает настройку **своего изолированного** Chrome-профиля
`var/chrome-profile`. Логин открывает собственное окно без отправок. При защите/неизвестной форме остановитесь.
Не требуется разрешать JavaScript через Apple Events: этот транспорт в starter отключён.

Для каждого резюме прочитайте снимок его страницы. Подставьте ключ из `candidate.cvs`
и точный ID из адреса **своего** резюме:

```bash
python portable.py sync-resume MAIN ВАШ_HH_RESUME_ID
```

Снимок привязывает ID, заголовок, опыт и навыки к `cv/current-cv-manifest.json`.
Команда только читает DOM. Если HH изменил разметку или данные неполны, она остановится:
не подставляйте вымышленные ID/доказательства успешной синхронизации.
Локальное резюме и HH-версию после правок сверяйте и синхронизируйте заново.

## 6. OpenAI и лимиты расходов

OpenAI для локального поиска и черновиков не обязателен. Для подключения существующего своего ключа:

```bash
python daily_delivery.py --configure openai
```

Ключ сохранится в отдельной записи вашего Keychain. Можно явно использовать `OPENAI_API_KEY`
в собственном окружении; если он установлен, он имеет приоритет. `doctor` показывает только факт его наличия.

Проверьте доступность выбранной модели и **актуальные собственные тарифы**.
Значения модели и ставок в шаблоне — не подтверждение текущей цены/доступности.
В `llm-config.json` задайте `model`, такой же `pricing_model`, `input_usd_per_million`,
`output_usd_per_million`, `max_calls_per_day`, `max_cost_usd_per_day`, `max_cost_usd_per_month`,
`max_output_tokens`, затем `pricing_confirmed_by_owner: true`.
Для платной работы нужны одновременно `enabled: true`, непустой `spending_approval`
и `ai_enabled: true` в `portable-config.json`.

Для регулярной обработки `spending_approval` должен иметь вид `recurring-user-approved:ВАША_ДАТА`,
`recurring_spending_approved: true`. Свободная редактура и автоматическая независимая проверка писем
используют `editorial_mode: cited_paraphrase`; для редактирования в ежедневном цикле также
`daily_editorial_enabled: true`. `exact_fragments` оставляет режим дословных фактов для ручного просмотра.
Лимит учитывает генерацию, отдельную проверку фактов и ответы на допустимые стандартные вопросы.
При неясном исходе резерв стоимости сохраняется; автоматических повторов нет.

## 7. Первый тест без сети и затем собственный поиск

Сначала, ещё с выключенными интеграциями:

```bash
python -m unittest discover -s tests -v
node --test tests/*.mjs
python portable.py demo
```

В `var/demo/` появятся `README.md`, `draft.txt`, `demo-report.json` с вымышленными данными.
Демо создаёт свою временную базу и не заполняет вашу рабочую `var/jobs.sqlite3`.
Сеть, дочерние процессы, Keychain и SMTP в тестовой границе блокируются.

После подключения **своего HH** выполните:

```bash
python portable.py search
```

Это реальный ограниченный поиск и локальные черновики, без браузерной отправки и платного AI.
После синхронизации своих HH-резюме для дневной подборки:

```bash
python portable.py daily
```

Пока AI/отправка/почта выключены, результат остаётся локальным. Не включайте их ради первого теста.

## 8. Где смотреть результаты

- `var/latest-run.json`, `var/hh/search-cache.json`: результаты поиска и детали;
- `var/outbox/`: локальные черновики и их JSON/EML;
- `var/daily-digest.html`, `var/daily-digest.json`: дневная подборка;
- `var/daily-digests/ДАТА/`: архив отчётов;
- `var/daily-email-preview.eml`/`.html`/`.txt`: почтовое превью;
- `var/daily-fit-decisions.json`, `var/daily-exceptions.json`: обоснования и исключения;
- `var/jobs.sqlite3`: вакансии, отклики, события, бюджеты и история.

```bash
python portable.py doctor
python pipeline.py status
```

`doctor` выводит абсолютные пути **вашей** копии, ID установки, отпечатки конфигураций,
счётчики базы и соответствие ID базы. Он не читает секреты и не подтверждает онлайн-авторизацию.
Последняя подтверждается вашим `hh_api.py setup`, ручным логином и тестом формы без отправки.
Не удаляйте историю и записи `send_uncertain`, чтобы «попробовать ещё раз».

## 9. Ручная проверка и включение откликов

По умолчанию просматривайте подборку и отправляйте вручную через HH.
Для автоматического режима сначала проверьте свои факты, письма, CV, зарплату и формулировки вопросов.
Тестовые задания, согласия, неизвестные обязательные вопросы и защиты HH остаются на ручную обработку.

При настроенном AI и своём HH можно оценить стоимость без платной генерации:

```bash
python application_batch.py --auto-prepare --plan-only
```

Эта команда делает реальные контрольные GET в HH для актуальности очереди, не отправляет отклики.
Затем отдельно разрешите в своём Codex платную подготовку в установленных лимитах и выполните:

```bash
python application_batch.py --auto-prepare
python application_batch.py --control-e2e
```

Первая команда может расходовать OpenAI-бюджет. Вторая подготавливает форму в своём браузере
без финальной отправки, проверяет историю, резюме, письмо и вопросы. Требуется `status: WORKS`.
Проверьте отчёт `var/local-browser-control-result.json` и подготовленные письма.

После осознанного принятия политики проверок:

```bash
python portable.py accept-dispatch-policy --acknowledge-reviewed
```

Задайте `dispatch-config.json`: `enabled: true`, `max_confirmed_per_day` не больше
`portable-config.json.max_applications_per_day`; в последнем включите `dispatch_enabled: true`.
Один реальный контрольный отклик запускается только по конкретному выбранному ID:

```bash
python application_batch.py --control-send ВАШ_ВЫБРАННЫЙ_HH_ID
```

**Эта команда реально отправляет отклик.** Не запускайте её как офлайн-тест.
Без успешного E2E, проверки качества и подтверждения в истории отправка блокируется.
После подтверждённого контрольного отклика ежедневный режим может отправлять в рамках лимитов:

```bash
python application_batch.py --autonomous
```

Автоматическая отправка также вызывается `portable.py daily`, если все разрешения, контрольные
доказательства и регулярный бюджет включены. При неопределённой отправке повтор запрещён.
Для возврата к ручному согласованию выключите `dispatch_enabled` и `dispatch-config.json.enabled`.
Расписание до окончания собственных контрольных проверок не устанавливайте.

## 10. Доставка отчётов и расписание

Почта необязательна. Выберите один канал, сначала проверьте получателя и превью.

**SMTP:**

```bash
python daily_delivery.py --configure smtp
```

Используются SMTP SSL и собственный пароль приложения. Настройка ничего не отправляет.
Укажите `recipient_confirmed: true`, включите `mail_enabled` в `portable-config.json` и
выполните отдельный реальный тест после появления дневного отчёта:

```bash
python daily_delivery.py --send-test-email
```

После получения письма установите `delivery-config.json.enabled: true`,
`delivery_approval: owner-approved:ВАША_ДАТА`, `transport: smtp`.
Принятие письма SMTP не доказывает доставку во входящие — её проверяет получатель.

**Свой Google Apps Script:** откройте `google-apps-script/README.md`.
Нужны свой Google-аккаунт, новый deployment URL, свой токен и свой фиксированный получатель
в Script Properties. Чужих URL или секретов в архиве нет.

**Расписание macOS:** `daily_time` задаёт время в **локальных системных часах macOS**.
`timezone` определяет границы дат/бюджетов; согласуйте её с часовым поясом своих запусков.
Перед установкой убедитесь, что абсолютные пути к Node/Playwright уже настроены,
все нужные ключи доступны через ваш Keychain, а папка больше не будет перемещаться.

```bash
python portable.py render-schedule
PLIST="$(python -c 'import portable_runtime as r; print(r.ROOT/"var"/("local.job-search-agent.starter."+r.identity()[:12]+".plist"))')"
mkdir -p "$HOME/Library/LaunchAgents"
cp "$PLIST" "$HOME/Library/LaunchAgents/"
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/$(basename "$PLIST")"
```

`render-schedule` только создаёт локальный plist, не устанавливает и не запускает задание.
Последние три команды выполняет новый владелец после своей проверки.
Уникальный label не совпадает с заданием другой установки. `RunAtLoad` выключен.
Журналы: `var/schedule.stdout.log`, `var/schedule.stderr.log`.
Первая реальная работа по расписанию и получение почты требуют вашей онлайн-проверки.

## 11. Отключение

Чтобы запретить новые внешние действия:

```bash
python portable.py pause
```

Команда выключает все внешние переключатели своей копии. Уже исполняющуюся сетевую операцию она не отменяет.
Для снятия **своего установленного** расписания:

```bash
PLIST="$(python -c 'import portable_runtime as r; print(r.ROOT/"var"/("local.job-search-agent.starter."+r.identity()[:12]+".plist"))')"
launchctl bootout "gui/$(id -u)" "$HOME/Library/LaunchAgents/$(basename "$PLIST")"
rm "$HOME/Library/LaunchAgents/$(basename "$PLIST")"
```

Удаляется только plist с ID этой копии. Базу/историю сохраните, секреты при необходимости отзовите
в своих аккаунтах и удалите соответствующие записи своего Keychain вручную.

## Граница проверки сборки

Проверены отдельное Python-окружение, установка npm-зависимостей, офлайн-цепочка,
один/несколько CV, пользовательские критерии, новая база, дедупликация, черновики,
бюджетные ограничения и запреты отправки. Подробности — `VALIDATION.md`.
Онлайн HH/OAuth, текущая DOM-разметка резюме и форм, реальный OpenAI, входящие письма,
новый Apps Script deployment и исполнение launchd на машине нового владельца не проверены.
